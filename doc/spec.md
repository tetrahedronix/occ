# occ - Orchestrator Specification

`occ` generates a reproducible container sandbox for AI coding agents from a
declarative `orchestrator-occ.yml`. It produces a `Dockerfile` and a standalone shell
launcher. The launcher has no runtime dependency on `occ`.

## orchestrator.yml schema

| Field               | Type             | Required | Description                                                                 |
|---------------------|------------------|----------|-----------------------------------------------------------------------------|
| `distro`            | string           | yes      | Base image, e.g. `debian:12`. Supported: `debian`, `ubuntu`, `alpine` (optionally with `:tag`). |
| `packages`          | list of strings  | no       | System packages installed in the image.                                     |
| `runtime`           | string           | yes      | `podman` or `docker`. Invalid values are rejected.                          |
| `podman_options`    | map              | no       | Podman-only invocation flags. Absent/ignored when `runtime: docker`.        |
| `podman_options.userns`   | string     | no       | Podman `--userns` value. Default `keep-id`.                                 |
| `podman_options.network`  | string     | no       | Podman `--network` value. Default `slirp4netns`.                            |
| `volumes`           | list of strings  | no       | `host:container` volume mounts added to the launcher.                       |
| `image`             | string           | no       | Image name the launcher runs. Default `ia-orchestrator`.                        |
| `script_name`       | string           | no       | Launcher filename. Default `orchestrator-occ.sh`.                                |

Unknown fields and unsupported `distro`/`runtime` values fail validation before
any template is rendered (no silently broken output).

## Generated artifacts

### Dockerfile

- Base image `FROM <distro>`.
- Package manager command branched on the distro family: `apt-get` for
  Debian/Ubuntu, `apk add` for Alpine.
- A provenance header on the first line:

  ```
  # Generated by occ <version> from <config> (sha256:<hash>)
  ```

  `<hash>` is the SHA-256 of the source `orchestrator-occ.yml`, used to detect stale or
  hand-edited output.

### Shell launcher

- Named `<script_name>`, written executable (`0755`).
- Mounts the project directory as `/workspace` and any `volumes` entries.
- Mounts the SSH agent when `$SSH_AUTH_SOCK` is set.
- Podman-only flags (`--userns`, `--network`) are emitted only when
  `runtime: podman`.
- Shell-evaluated values (`$SSH_AUTH_SOCK`, `$(cd "$(dirname "$0")" ...)`,
  `$HOME`, ...) survive generation untouched: only values known at generation
  time go through `text/template`.

## Template overrides

Default templates are embedded in the binary (`internal/templates/`). Per-file
override is supported: a file `<template-dir>/Dockerfile.tmpl` or
`<template-dir>/orchestrator-occ.tmpl` (default `<template-dir>` = `.occ/templates/`)
replaces that template only. A custom `Dockerfile.tmpl` does not force a custom
launcher template and vice versa.

## Overwrite policy

`occ generate` refuses to overwrite an existing `Dockerfile` or launcher unless
`--force` is given. `--diff` prints a line diff of the would-be changes and
writes nothing.
